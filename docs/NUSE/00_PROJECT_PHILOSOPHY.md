# NUSE - Project Philosophy

Version: 1.0.0

Status: Stable

---

# 1. Mission

The NBA Universal Simulation Engine (NUSE) is a deterministic, probabilistic, causal and fully explainable basketball simulation engine designed to model every relevant aspect of the NBA ecosystem.

Its objective is not merely predicting statistics.

Its objective is reproducing reality as faithfully as possible.

Every prediction generated by NUSE must emerge from a coherent representation of basketball rather than from isolated statistical estimation.

---

# 2. Primary Goal

NUSE must be capable of projecting:

- Individual player seasons.
- Team seasons.
- Complete box scores.
- Advanced metrics.
- Team performance.
- Awards.
- Playoffs.
- Trades.
- Lineup changes.
- Coaching changes.
- Injury scenarios.

using a single unified simulation framework.

---

# 3. Core Philosophy

Statistics are never considered knowledge.

Statistics are considered consequences.

Knowledge exists only inside:

- player abilities
- team context
- coaching philosophy
- tactical systems
- possession dynamics
- decision making
- event generation

Every visible statistic must emerge naturally from these components.

---

# 4. Causality Principle

Every variable inside NUSE must have explicit causal parents.

No variable may exist without explaining:

- where it comes from
- what influences it
- what it influences

Hidden magic variables are forbidden.

---

# 5. Explainability Principle

Every prediction must automatically generate an explanation.

Example:

Projected Points Per Game

27.8

Explanation

+0.9 due to increased minutes

+0.6 due to higher offensive usage

+0.4 due to improved shooting efficiency

-0.3 due to stronger defensive schedule

Every prediction inside NUSE must be decomposable into its contributing factors.

---

# 6. Modular Architecture

Every subsystem shall be replaceable without affecting unrelated components.

Examples:

Replacing the injury model must not require changing:

- shooting
- passing
- rebounding
- advanced metrics

Replacing lineup chemistry must not modify:

- player physical profile

- player shooting model

Modules communicate only through well-defined interfaces.

---

Basketball shall be represented using hierarchical entities.

League

↓

Franchise

↓

Team

↓

Coach

↓

Roster

↓

Player

↓

Lineup

↓

Game

↓

Possession

↓

Event

↓

Statistics

↓

Advanced Metrics

↓

Historical Record

No calculation may violate this hierarchy.

---

# 8. Possession-Centric Simulation

The possession is the atomic unit of basketball.

Games are sequences of possessions.

Statistics emerge from possessions.

Seasons emerge from games.

Career data emerge from seasons.

---

# 9. Observable vs Latent Variables

NUSE distinguishes between:

Observable variables

Directly measurable.

Latent variables

Estimated internal player properties.

Derived variables

Computed from previous variables.

Probabilistic variables

Represent uncertainty.

No variable may belong to multiple categories simultaneously.

---

# 10. Data Source Independence

NUSE is independent of any particular API.

Implementations may use:

NBA Stats API

ESPN

Basketball Reference

Second Spectrum

Synergy

Cleaning the Glass

or equivalent providers.

The specification defines required information, never mandatory providers.

---

# 11. Mathematical Independence

The specification never forces a mathematical implementation.

Possible implementations include:

Linear models

Bayesian models

Gradient boosting

Neural networks

Graph neural networks

Monte Carlo simulation

Hybrid systems

Only behavioural correctness matters.

---

# 12. Traceability

Every output must be traceable.

Example:

↓

↓

Usage

↓

Possessions

↓

Minutes

↓

Availability

↓

Physical State

↓

Health

↓

The engine must always be capable of reconstructing this dependency tree.

---

# 13. Validation

Every module must define:

Expected behaviour

Evaluation metrics

Acceptable error

Validation datasets

Known limitations

No module shall be considered complete without validation.

---

# 14. Extensibility

The specification must remain valid for future NBA seasons.

New statistics.

New tracking technologies.

New APIs.

New advanced metrics.

New machine learning models.

must be incorporable without rewriting the specification.

---

# 15. Single Source of Truth

The documentation contained inside /docs/NUSE is the authoritative description of the engine.

Implementation must follow the specification.

The specification must never be rewritten to justify implementation mistakes.

---

# 16. Ultimate Objective

NUSE aims to become a complete digital twin of NBA basketball.

Every projection should represent not only what is expected to happen,

but also why it is expected to happen,

how confident the engine is,

which variables contribute to the prediction,

and how alternative scenarios would modify the outcome.
